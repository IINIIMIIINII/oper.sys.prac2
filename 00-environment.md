# Частина 0. Середовище

Виконується на першому занятті разом із викладачем. Не оцінюється, але без неї не буде решти.

## Що потрібно

Віртуальна машина з Linux, компілятором C і sudo. Рекомендовано Ubuntu 26.04. VM знадобиться і в наступних лабораторних, тож налаштуйте її один раз. Docker не підійде: частина спостережень потребує власного ядра під вашим контролем.

### Варіант 1: Vagrant

Vagrant створює і налаштовує VM однією командою за `Vagrantfile`, який лежить у каталозі `lab2`. Користуватися ним не обов'язково: це лише швидший шлях до того самого, що й у варіанті 2.

1. Встановіть [VirtualBox](https://www.virtualbox.org/wiki/Downloads) і [Vagrant](https://developer.hashicorp.com/vagrant/install). Підходять Windows, Linux і macOS.
2. У каталозі `lab2`:

   ```sh
   vagrant up      # перший раз завантажує Ubuntu і ставить пакети, кілька хвилин
   vagrant ssh     # увійти у VM
   cd /vagrant     # це каталог lab2 з вашого комп'ютера
   ```

Редагуйте файли у звичному редакторі на своєму комп'ютері, а збирайте й запускайте у VM. `vagrant halt` вимикає VM.

### Варіант 2: VM вручну

Встановіть Ubuntu 26.04 у будь-який гіпервізор: VirtualBox, VMware, Hyper-V на Windows, UTM або Parallels на macOS. Достатньо 2 ГіБ RAM і 20 ГіБ диска. Потім пакети:

```sh
sudo apt update
sudo apt install build-essential strace util-linux time manpages-dev
```

Скопіюйте каталог `lab2` у VM: через `git clone`, `scp` або спільну теку гіпервізора.

### WSL

Якщо ви вже користуєтеся WSL2 і знаєте його, для цієї лабораторної він підійде. Для ЛР5 все одно знадобиться VM.

## Перевірка

```sh
cd lab2         # у Vagrant: cd /vagrant
sh check_env.sh
```

Усі рядки мають починатися з `ok`. Скрипт також пробує скомпілювати програму з AddressSanitizer і переконатися, що він ловить помилку.

## Розминка: перша програма і strace

1. Створіть `hello.c`:

   ```c
   #include <stdio.h>

   int main(void)
   {
       printf("hello\n");
       return 0;
   }
   ```

2. Зберіть і запустіть. Прапорці `-Wall -Wextra` вмикають попередження, `-g` додає інформацію для налагоджувача та ASan:

   ```sh
   gcc -Wall -Wextra -g hello.c -o hello
   ./hello
   echo $?
   ```

   `$?` містить код виходу останньої команди. Змініть `return 0` на `return 3` і перевірте.

3. Подивіться, які системні виклики робить програма:

   ```sh
   strace ./hello
   ```

   Знайдіть у виводі `execve`, `brk` або `mmap`, `write(1, "hello\n", 6)` та `exit_group`. Усе інше робить libc під час запуску. Зверніть увагу, що `printf` з вашої програми перетворився на `write` із дескриптором 1.

4. Порівняйте з «дорослою» програмою:

   ```sh
   strace -c ls          # підсумкова таблиця виклики/кількість
   strace -e trace=openat ls   # лише відкриття файлів
   ```

5. Подивіться на пам'ять свого shell:

   ```sh
   cat /proc/self/maps     # maps процесу cat, бо self — це той, хто читає
   cat /proc/$$/maps       # maps вашого bash ($$ — його PID)
   ```

   Поки що просто помітьте: є [heap], є [stack], є багато бібліотек і є рядки без імені. Що це все означає, розберемо в частині 1.

## Довідка, якою ви будете користуватися

- `man 2 write`, `man 2 mmap`, `man 3 malloc`: розділ 2 — системні виклики, 3 — бібліотечні функції. У man-сторінці завжди є розділ RETURN VALUE і ERRORS.
- `man 5 proc`: формат файлів у `/proc`, зокрема `maps`, `statm`, `status`.
- `errno` та `perror("назва виклику")`: як дізнатися, чому виклик повернув -1.
